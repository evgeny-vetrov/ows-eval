# Движок интерпретатора сценариев Фабулы — дизайн

Импорт: `ai.gena.services.fabula.engine`. Зависимости пакета: стандартная библиотека,
pydantic v2, PyYAML, jsonschema. Больше ничего (проверяется тестом
`tests/architecture`).

## 1. Слои

```
model    значения, общие для всех слоёв: событие, фильтр, ошибка (RFC 7807),
         дескрипторы каталогов, стимулы, команды, наблюдения, контекст исполнения
ports    интерфейсы всего внешнего (typing.Protocol) с контрактами в docstring,
         чистые функции externalize/internalize
dsl      парсер YAML/JSON с позициями, валидатор профиля, компиляция в граф
core     чистая функция перехода: Interpreter.start / Interpreter.apply
runtime  эталонный асинхронный хост поверх эффектных портов
testing  реализации портов в памяти, фейковые часы, раннер сценариев, пилот
```

Правило зависимостей: `model ← ports ← dsl ← core ← runtime`; `testing` может
импортировать всё. `dsl` и `core` не импортируют `runtime` и `testing`.

## 2. Ядро

```python
interpreter = Interpreter(expressions=..., matcher=..., schemas=..., limits=EngineLimits())
t = interpreter.start(scenario, input, context, at, fabula_id="f-1")
t = interpreter.apply(t.state, stimulus)
# t.state: FabulaState, t.commands: tuple[Command], t.observations: tuple[Observation]
```

* Ядро синхронное, без ввода-вывода, часов, случайности и глобального состояния.
  Единственное поле экземпляра, кроме портов, — мемо-кэш скомпилированных графов по
  дайджесту сценария (чистая функция, на результат не влияет).
* `fabula_id` передаёт хост: сгенерировать его ядро не может (см. «Решения»).
* Входное состояние не мутируется. Любое исключение, кроме объявленных
  (`InvalidScenario`, `InvalidState`), заворачивается в `CoreError`; хост получает
  его, а исходное состояние остаётся целым.
* Внутри перехода работает «агенда» — очередь пунктов `Enter / Finish / Fail`.
  Рекурсии Python нет: переход по графу — это цикл по агенде. На переход есть бюджет
  шагов (`max_steps_per_transition`); если он исчерпан, ядро выпускает
  `StartTimer(yield, fire_at=at)` и продолжает по `TimerFired`. Так длинный цикл
  не блокирует хост и оставляет безопасные точки.

### 2.1 Стимулы

`InvocationFinished`, `TimerFired`, `EventDelivered`, `Control` — закрытое
размеченное объединение по полю `kind`. У всех есть `stimulus_id` и `at`.

### 2.2 Команды

`InvokeCapability`, `CancelInvocation`, `StartTimer`, `CancelTimer`, `Subscribe`,
`Unsubscribe`, `PublishEvent`, `Completed`, `Failed`, `Cancelled`.

### 2.3 Идентификаторы

```
op_id = "{fabula_id}/{node_path без ведущего /}@{visit}.{attempt}/{kind}"
        f-1/runAgent@1.1/call          вызов кубика
        f-1/runAgent@1.1/timeout       дедлайн задачи
        f-1/waitMerge@1.1/sub.0        подписка фильтра 0
        f-1/guard@1.2/retry            пауза перед ретраем
        f-1/@workflow/timeout          дедлайн сценария
        f-1/@workflow/yield.3          уступка по бюджету шагов
```

* `visit` — счётчик входов в узел; растёт при каждом входе (следующий шаг, итерация
  цикла, `Goto`, перезапуск после смены версии).
* `attempt` — номер попытки внутри визита: ретрай `try` (для узла `try`), встроенный
  ретрай кубика и `RetryTask` (для самого узла). Пара `(visit, attempt)` уникальна
  для узла, поэтому id уникальны, а при реплее совпадают.
* Перенос таймера (`ExtendDeadline`) выпускает новый id с суффиксом поколения
  `~2`, `~3`: опоздавшее срабатывание старого таймера отличимо от нового.

### 2.4 Состояние

`FabulaState` (pydantic v2, JSON без потерь):

| поле | смысл |
|---|---|
| `schema_version`, `engine_version` | версия схемы состояния и версия движка, записавшего его |
| `semantics` | версия движка на старте и флаги семантики, зафиксированные на старте |
| `fabula_id`, `status` | `running / waiting / paused / completed / failed / cancelled` |
| `scenario` | `ScenarioSnapshot`: документ + закреплённые дескрипторы кубиков и событий + дайджест |
| `execution_context` | `run_as`, триггер, метки; ядро не интерпретирует |
| `workflow_input`, `data` | вход сценария и `$context` |
| `frames` | явный курсор: кадры, ключ — путь узла (см. 2.5) |
| `inflight` | операции в полёте: id → вид, владелец, параметры |
| `visits` | счётчики визитов по путям (не больше числа узлов во всех версиях, через которые прошла фабула) |
| `agenda` | незавершённая работа (только при уступке или на паузе) |
| `paused_queue` | стимулы, пришедшие на паузе |
| `recent_stimuli`, `recent_controls` | окна дедупа ограниченного размера |
| `output`, `problem`, `failed_node`, `last_error` | результат, терминальная ошибка и её узел, последняя ошибка |
| `yield_seq` | номер последней уступки по бюджету шагов |

Размер состояния ограничен: журнал уходит наблюдениями, окна дедупа, очередь паузы и
буферы `listen` имеют потолки из `EngineLimits`. Число кадров не больше числа узлов.

### 2.5 Курсор

Активные кадры хранятся словарём `path → Frame`. В любой момент у узла не больше
одного активного кадра: ветви `fork` имеют разные пути, итерации циклов и ретраи
последовательны. Родитель кадра — префикс пути, поэтому словарь и есть явный стек
(дерево — из-за `fork`). Виды кадров: `workflow`, `do`, `try`, `for`, `fork`, `call`,
`wait`, `listen`, `leaf` (`set`, `switch`, `raise`, `emit` — живут в пределах шага).

Кадр хранит визит, попытку, сырой и преобразованный вход, id своего таймера
дедлайна и состояние вида: текущий дочерний узел, индекс и аккумулятор цикла, фазу
`try`, статусы ветвей `fork`, подписки и буфер `listen`.

### 2.6 Поток данных

Для задачи: сырой вход → `input.schema` → `input.from` → задача → сырой выход →
`output.as` → `output.schema` → `export.as` → `export.schema` → `$context`.
Преобразованный выход — сырой вход следующей задачи.

Аргументы выражений: `$context`, `$input` (преобразованный вход задачи), `$output`
(в `output.as` — сырой выход, в `export.as` — преобразованный), `$task`, `$workflow`,
`$runtime`, плюс переменные циклов (`$item`, `$index` или свои имена) и ошибки
(`$error` или имя из `catch.as`).

## 3. Порты

### Чистые (передаются в ядро)

* `ExpressionEngine`: `compile(text) -> CompiledExpression | ExpressionDiagnostics`,
  `evaluate(compiled, input, args)`. Ошибка вычисления — `ExpressionError`
  (становится ошибкой `expression` сценария). Лимиты: длина текста (в `compile`),
  размер входа и «время» вычисления. Время меряется детерминированно — шагами
  вычислителя. Адаптер, умеющий только стенные часы, обязан при превышении бросать
  `ExpressionResourceExhausted`: ядро превращает её в `CoreError` и не фиксирует
  переход, чтобы недетерминизм не попал в историю. `CompiledExpression.variables` —
  найденные ссылки на переменные (`$context.a.b`); нужны для отчёта о смене версии.
* `EventMatcher.matches(filter, event) -> bool`.
* `SchemaValidator.check_schema(schema)`, `validate(schema, instance)` — Draft 7.

### Каталоги (валидатор и хост)

* `CapabilityCatalog.resolve(ref) -> CapabilityDescriptor | None`.
* `EventCatalog.resolve(type) -> EventTypeDescriptor | None`.

При публикации сценария найденные дескрипторы закрепляются в `ScenarioSnapshot`.
Ядро каталогов не видит и работает с закреплёнными дескрипторами: изменение каталога
не меняет поведение идущих фабул и реплей.

### Эффектные (только хост)

`CapabilityInvoker`, `EventSubscriptions`, `EventPublisher`, `TimerService`,
`FabulaStore`, `ScenarioRepository`, `BlobStore`, `JournalSink`, `Clock`.
Контракты — в docstring модулей `ports/effects.py` и `ports/storage.py`. Главное:

* `invoke`, `subscribe`, `publish`, `schedule` идемпотентны по своему id;
* результаты и события доставляются хотя бы один раз, возможны дубли и опоздания;
* повторный `subscribe` с тем же id и более поздним `expires_at` продлевает подписку;
* `FabulaStore.save` — оптимистичная блокировка по версии и атомарная запись outbox
  (команды и наблюдения перехода). `load` возвращает сохранённый документ (JSON
  состояния после `externalize`), версию и неподтверждённый outbox: хранилище не
  знает о моделях ядра.

`externalize(document, threshold) -> (document, blobs)` и
`internalize(document, fetch)` — чистые функции над JSON-формой состояния. Ссылка на
значение — `{"$blob": "sha256:…", "size": n}`, адрес — хеш содержимого. Словари с
ключами `$blob`/`$literal` экранируются, поэтому преобразование без потерь.

## 4. DSL

### 4.1 Профиль OWS 1.0.3

Разрешено: `do`, `set`, `switch`, `raise`, `wait`, `call` (только кубики каталога,
`name:version@provider`), `try/catch/retry`, `for` (+`while`), `listen`
(`to.one|any|all`, `until`, `foreach`, `read`), `emit`, `fork` (`branches`, `compete`),
`then`, `input.from`, `output.as`, `export.as`, `if`, `timeout` задач и сценария,
`input.schema`/`output.schema` сценария, `schedule.after`, `use.errors`,
`use.retries`, `use.timeouts`.

Запрещено (у каждой конструкции свой код диагностики): `run`, `use.extensions`,
`use.authentications`, `use.secrets`, `$secrets`, `schedule.every|cron|on`,
`call: http|grpc|openapi|asyncapi`, `use.functions`, `use.catalogs`, внешние схемы
(`schema.resource`).

Лимиты: документ ≤ 256 КБ, узлов ≤ 300, вложенность ≤ 10, `wait` и таймауты
≤ 180 дней. Потолок итераций `for` — `EngineLimits.max_for_iterations`.

### 4.2 Пути узлов

Корень — `/`. Задача верхнего уровня — `/имя`. Дети `do`, `for`, ветви `fork` и тело
`listen.foreach` — `/родитель/имя`. У `try` два списка: `/g/try/имя` и
`/g/catch/имя`. Имена: `[A-Za-z0-9][A-Za-z0-9_-]*`, кроме `continue`, `exit`, `end`.

### 4.3 Диагностика

`Diagnostic{code, message, severity, pointer, node, line, column}`. Строка и колонка
берутся из карты позиций парсера, ссылки на кубики и типы событий проверяются через
каталоги. Разбор и валидация работают без сети и хоста.

## 5. Семантика задач

* **then**: `continue` (по умолчанию), `exit` (завершить текущий составной узел),
  `end` (завершить сценарий с выходом задачи), имя задачи того же списка.
* **if** ложно → `NodeSkipped`, выход = сырой вход, переход `continue`.
* **set** → выход = вычисленное значение. **switch** → первая подходящая ветка,
  выход = вход. **raise** → ошибка (`instance` по умолчанию — JSON pointer задачи).
* **call** → проверка входа по схеме, `InvokeCapability`, таймер дедлайна (таймаут
  задачи или дескриптора). Результат проверяется по схеме выхода. Таймаут →
  `CancelInvocation` (если кубик отменяемый) и ошибка `timeout`. Встроенный ретрай
  дескриптора — новая попытка того же визита.
* **wait** → `StartTimer`. Длительность (ISO 8601, объект, выражение) или
  `{until: момент}`.
* **try**: ошибка тела → `errors.with` (точное совпадение полей), `when`,
  `exceptWhen` → ретрай (если есть и лимиты позволяют) → иначе `catch.do` или выход
  = вход `try`. `catch` с `retry`, но без `do`, после исчерпания ретраев ошибку не
  глотает, а пробрасывает. Непойманная ошибка идёт вверх.
* **retry**: задержка `n`-го ретрая: constant `d`, linear `d·n`, exponential
  `d·2^(n-1)`, плюс джиттер `from + (to-from)·u`, где
  `u = sha256("{fabula_id}|{path}|{n}")[:8] / 2^64`. `limit.attempt.count` — число
  ретраев после первой попытки, `limit.attempt.duration` — таймаут одной попытки,
  `limit.duration` — общее время от начала первой попытки.
* **for**: `in` вычисляется на входе и хранится в кадре; `while` — перед каждой
  итерацией; вход итерации — выход предыдущей (свёртка), выход `for` — выход
  последней итерации. Потолок итераций — ошибка `runtime`.
* **listen**: одна подписка на фильтр. Фильтр = предикаты `eq` из `with` +
  корреляция (`from` — простой путь, `expect` вычисляется при входе). `since` —
  момент входа, `expires_at` — ближайший дедлайн + `subscription_expiry_margin`
  (нет дедлайна — нет срока). Доставка: дедуп по `delivery_key`, перепроверка
  `EventMatcher`. `one`/`any` — первое подходящее; `all` — все фильтры, каждый
  отписывается после удовлетворения; `any`+`until` — поток до условия или до события
  `until`-стратегии; `foreach` — обработка каждого события телом (свёртка), события
  во время обработки буферизуются. Выход без `foreach` — массив событий в виде `read`.
* **emit** → `PublishEvent`, `event.id = emit_id`, `time = at`, выход = вход.
* **fork**: ветви стартуют по порядку объявления, в ширину: каждая ветвь делает
  первый шаг раньше, чем начнутся шаги вложенных узлов. Без `compete` — выход
  массив выходов ветвей по порядку, ошибка ветви отменяет остальные и роняет
  `fork`. С `compete` — побеждает первая завершившаяся, остальные закрываются;
  ветвь, которая ещё не успела стартовать, просто не стартует.

При любом выходе из скоупа (завершение, ошибка, `compete`, `Goto`, `exit`, `end`,
отмена, смена версии) все операции поддерева закрываются: `CancelInvocation`
(для отменяемых кубиков), `CancelTimer`, `Unsubscribe`.

## 6. Ошибки

`Problem{type, status, title, detail, instance}` (RFC 7807), `instance` по умолчанию —
JSON pointer задачи. Стандартные типы OWS
`https://serverlessworkflow.io/spec/1.0.0/errors/{configuration, validation,
expression, authentication, authorization, timeout, communication, runtime}`.
Необработанная ошибка → статус `failed` и команда `Failed`. Цепочка кадров до
упавшего узла сохраняется, поэтому `RetryTask`, `SkipTask` и `Goto` могут
восстановить фабулу. `completed` и `cancelled` окончательны.

## 7. Вмешательства

`Control{request_id, actor, reason, action}`. Ядро проверяет допустимость в текущем
состоянии, применяет действие целиком или отклоняет с причиной
(`ControlRejected{code, message}`), оставляет наблюдение с автором и причиной.
Повтор `request_id` даёт `StimulusIgnored(duplicate)` и ничего не меняет.

| действие | допустимо | эффект |
|---|---|---|
| `Pause` | running, waiting | статус `paused`; стимулы копятся в `paused_queue` |
| `Resume` | paused | отложенная агенда, затем накопленные стимулы по порядку |
| `Cancel` | не окончательный | закрыть всё в полёте, `Cancelled` |
| `SkipTask(node, output)` | узел активен | закрыть поддерево, завершить узел с `output` как сырым выходом |
| `RetryTask(node)` | узел активен или упал | закрыть поддерево, тот же визит, попытка +1 |
| `Goto(node, input?, allow_scope_change?)` | см. ниже | закрыть покидаемое, войти в `node` |
| `PatchContext(patch)` | не окончательный | RFC 7386 merge patch над `$context` |
| `CompleteWait(node, event \| output)` | активный `wait`/`listen` | удовлетворить ожидание |
| `ExtendDeadline(node, fire_at)` | активный узел с дедлайном; `/` — сценарий | перенести таймер, продлить подписки |
| `SwapVersion(...)` | не окончательный, агенда пуста | см. раздел 8 |

На паузе допустимы все действия, кроме `Pause`. Команды закрытия выпускаются сразу,
а вход в новые узлы откладывается до `Resume`: новых операций на паузе нет.
Исключение — `ExtendDeadline`: перенос уже существующего таймера выпускает
`CancelTimer` + `StartTimer` сразу, это не новая работа. После `Resume` сначала
исполняется отложенная агенда, затем накопленные стимулы по порядку прихода;
их время — момент `Resume`.

Восстановление упавшей фабулы (`RetryTask`, `SkipTask`, `Goto`): у кадров цепочки
снимается отметка ошибки, дедлайны предков и сценария заводятся заново от момента
восстановления (с новым поколением id), подписки предков-`listen` возобновляются
с новыми id и прежним `since` (события, пришедшие за время простоя, придут через
lookback), отменённые ветви `fork` на цепочке стартуют заново.

Правила `Goto(T)`:

1. `T` существует и не корень. Контейнер `S` — родитель `T` вместе со списком.
2. Если `S` активен и сейчас исполняет этот список, покидается его текущий ребёнок
   `C`. Если `C` — лист, это переход в том же скоупе: разрешён всегда. Если `C` —
   составной узел (`do`, `for`, `fork`, `try`, `listen` с `foreach`), переход выходит
   из вложенного скоупа и требует `allow_scope_change`.
3. Если `S` не активен, нужен спуск от ближайшего активного предка. Он разрешён
   только с `allow_scope_change` и только через «конструируемые» контейнеры: `do`
   и тело `try`. Вход в тело `for`, ветку `fork`, тело `listen.foreach` и блок
   `catch` запрещён: для них нет состояния (элемента, соседних веток, ошибки).
4. Вход `T` — явный `input` или сырой вход покидаемого узла.
5. Внутри одной ветки `fork` переход не трогает остальные ветки.
6. Сама ветка `fork` целью быть не может: у неё нет «соседей по списку», которые
   можно покинуть.

## 8. Смена версии

`analyze_swap(state, new_scenario, mapping, context_migration=None) -> SwapReport` —
чистая функция (метод `Interpreter`, ей нужен вычислитель выражений). Для каждого
активного кадра: цель = `mapping[path]`, иначе тот же путь. Кадр **сохраняется**,
если цель существует, вид тот же, родитель цели — образ родителя кадра и параметры
совместимы:

* `call` — тот же `capability_ref`;
* `listen` — та же стратегия, те же типы, фильтры, корреляция, `read`, `foreach`;
* `wait` — всегда (таймер остаётся со старым `fire_at`);
* `for`, `do`, `try`, `fork` — вид совпадает; у `fork` совпадает `compete` и все
  активные ветви существуют; `try` в фазе `catch` — `catch.do` существует.

Несохраняемый кадр **перезапускается**, если для него есть явная строка `mapping`:
его операции отменяются, а целевой узел (в том же скоупе) получает вход кадра.
Если такой строки нет, смена **отклоняется** с отчётом. Отчёт: куда встанет курсор,
какие операции сохранятся или будут отменены, какие узлы перезапустятся, каких
`$context`-ключей не хватит новой версии (после миграции), ошибки.

На завершённой или отменённой фабуле `analyze_swap` возвращает неприменимый отчёт с
тем же текстом, что и отказ `SwapVersion`.

Смена применяется одним переходом: снимок сценария, переименование кадров и
владельцев операций, команды закрытия, вход в перезапускаемые узлы, миграция
контекста. Счётчики визитов переносятся по сопоставлению и не удаляются, поэтому
id операций остаются уникальными и после нескольких смен. Флаги семантики не
меняются. Сохранённые операции оставляют прежние id: внешние системы их знают.

## 9. Флаги семантики

`semantics.flags` фиксируются на старте из `Interpreter.new_fabula_semantics`
(по умолчанию `core.semantics.DEFAULT_FLAGS`). Ядро читает флаги только из
состояния. Сейчас есть один флаг: `listen_all_order` — порядок событий в выходе
`listen.to.all`: `declaration` (текущий) или `arrival` (исходное поведение).

## 10. Наблюдаемость

Наблюдения: `FabulaStarted`, `NodeStarted`, `NodeCompleted`, `NodeFailed`,
`NodeSkipped`, `NodeCancelled`, `RetryScheduled`, `Waiting`, `ControlAccepted`,
`ControlRejected`, `StimulusIgnored`, `StimulusQueued`, `StatusChanged`, `SafePoint`,
`FabulaCompleted`, `FabulaFailed`, `FabulaCancelled`, `ScenarioSwapped`.
`core.journal.build_journal` собирает журнал шагов (узел, визит, попытка, времена,
вход, выход, ошибка), `core.projection.project` — проекцию для API (статус, текущие
узлы, ожидания, последняя ошибка).

Ограничения `Goto`, закреплённые тестами: цель — ветвь `fork` → отказ
`fork_branch`; выход из вложенного скоупа без разрешения → `cross_scope`; спуск в
тело `for`, `listen.foreach` или `catch` → `not_constructible`; на упавшей фабуле
якорь должен лежать на цепочке ошибки → иначе `not_on_failure_path`.

## 11. Хост

`runtime.Host`: на каждый стимул — загрузить состояние (и сначала дослать
неподтверждённый outbox) → `apply` → `save(expected_version, outbox)` → исполнить
команды → записать наблюдения (идемпотентно по версии) → подтвердить outbox.
Стимулы одной фабулы обрабатываются под `asyncio.Lock`, а между процессами —
оптимистичной блокировкой: при `VersionConflict` хост перечитывает состояние и
применяет стимул заново. После падения `recover()` дошлёт outbox всех фабул; повтор
команд безопасен благодаря идемпотентным id. Большие значения уходят в `BlobStore`
через `externalize` перед записью. Из-за доставки «хотя бы один раз» после падения
в журнале может появиться запись `StimulusIgnored(duplicate)` о повторной доставке;
всё остальное совпадает с прогоном без падения (проверяется тестом на каждой точке
падения пилота).

## 12. Отклонения от OWS 1.0.3

1. `call` — только кубики каталога в форме `name:version@provider`.
2. `schedule` — только `after`, и это задержка перед первым запуском, а не повтор
   после завершения.
3. `wait` принимает ещё и `{until: момент}` (FR-4 требует ожидание до момента).
4. `listen.with`: значения — литералы или выражения, вычисляемые один раз при входе;
   предикат-выражения по событию не поддерживаются, потому что фильтр должен один в
   один переводиться во внешнюю систему подписок.
5. `correlate.expect` обязателен, `from` — только простой путь.
6. Каждый фильтр `listen` обязан задать `with.type`; `any: []` запрещён.
7. `until`-выражение вычисляется после каждого события, `.` — это событие.
8. `read: raw` эквивалентен `data`: конверт уже разобран.
9. `for` и `listen.foreach` — свёртка: вход итерации = выход предыдущей.
10. Сценарный `evaluate.mode` — только `strict`, язык — только `jq` (исполняет порт).
11. `$secrets` и `use.secrets` запрещены.
12. `$workflow.definition` содержит только блок `document`.
13. Имена задач ограничены `[A-Za-z0-9][A-Za-z0-9_-]*`.
14. `then` на ветви `fork` запрещён (`then.fork_branch`): ветви идут рядом, а не
    последовательно, и директива на ветви молча ничего бы не делала.
15. Имена переменных циклов, `foreach` и `catch.as` не могут перекрывать встроенные
    (`$context`, `$input`, …).

## 13. Решения

Решения, принятые без спроса; каждое закреплено тестом.

1. **`fabula_id` — параметр `start`.** Ядро не генерирует id, а выводить его из
   входа нельзя: две фабулы с одинаковым входом столкнутся.
2. **Сценарий хранится в состоянии** (`ScenarioSnapshot`, ≤ 256 КБ плюс
   дескрипторы). Так `apply(state, stimulus)` самодостаточен, выгрузка-загрузка
   тривиальна, а `externalize` уносит снимок в `BlobStore`.
3. **Дескрипторы каталогов закрепляются при публикации.** Изменение каталога не
   меняет поведение идущих фабул.
4. **Дедуп `stimulus_id` — окно последних N id** (`max_recent_stimuli`). Всё, что
   старше окна, отсекается структурно: результат не своей операции — «опоздал»,
   ключ доставки уже виден подписке — «дубль». `request_id` вмешательств хранится в
   отдельном окне вместе с решением.
5. **Стимул к операции не в полёте** → `StimulusIgnored(late)`; событие, не прошедшее
   перепроверку фильтра, → `StimulusIgnored(filter_mismatch)`.
6. **`Failed` восстановим.** Цепочка кадров к упавшему узлу остаётся, `RetryTask`,
   `SkipTask`, `Goto` возвращают фабулу в работу. `completed` и `cancelled`
   окончательны.
7. **`SkipTask(output)`** — это сырой выход задачи: `output.as` и `export.as`
   применяются как обычно.
8. **`CompleteWait(event)`** для `listen` без `foreach` добавляет событие к
   принятым и завершает узел; с `foreach` принимается только `output`.
9. **`ExtendDeadline`** для `wait` переносит момент пробуждения, для остальных
   узлов — таймер дедлайна, для `/` — дедлайн сценария; подписки продлеваются
   повторным `Subscribe` с тем же id.
10. **`PatchContext`** — RFC 7386 merge patch.
11. **На паузе** принимаются все вмешательства, кроме `Pause`; закрытие операций
    выпускается сразу, вход в узлы — после `Resume`. Очередь паузы ограничена
    `max_paused_stimuli`; переполнение → `StimulusIgnored(paused_backlog_full)`.
12. **Ошибка ветви `fork`** (и с `compete`, и без) отменяет остальные ветви и роняет
    `fork`.
13. **Выход `listen.to.all`** упорядочен по объявлению фильтров (флаг
    `listen_all_order`).
14. **`until`-стратегия**: её события в выход не попадают.
15. **Подписка без дедлайна** выпускается без `expires_at`; утечки закрывает явный
    `Unsubscribe`.
16. **Отмена кубика исполнителем** (`outcome=cancelled` без нашего запроса) —
    ошибка `runtime` «Invocation cancelled by executor».
17. **Пропущенный по `if` узел** не применяет свой `then`.
18. **Без `catch.do`** выход пойманного `try` равен его преобразованному входу; вход
    `catch.do` — тот же преобразованный вход, ошибка доступна как `$error`.
19. **Встроенный ретрай кубика** (из дескриптора) действует всегда, независимо от
    внешнего `try`; он повторяет вызов в том же визите с новой попыткой.
20. **Время вычисления выражений** меряется шагами вычислителя, а не часами.
21. **Смена версии** требует пустой агенды, иначе отказ «not at rest».
22. **Отсутствующие переменные** в отчёте смены версии — предупреждение, не отказ.
23. **Путь фильтра**, которого нет в схеме события, — ошибка, если в этом месте
    схемы объявлены `properties` и не разрешены `additionalProperties: true`.
24. **Предикат по отсутствующему атрибуту** ложен для всех операторов, кроме
    `exists: false`. `matches` — поиск (`re.search`), не полное совпадение.
25. **`emit.event.with.source`** по умолчанию — `fabula:{fabula_id}`.
26. **`schedule.after`**: дедлайн сценария отсчитывается от реального старта, а не
    от момента создания фабулы.
27. **Длинные переходы**: бюджет шагов на переход, затем уступка таймером
    `yield` с `fire_at = at`.
28. **`catch` только с `retry`** после исчерпания ретраев пробрасывает ошибку;
    `catch` без `retry` и без `do` ошибку глотает (выход — вход `try`).
29. **Время не идёт назад**: переход использует `max(stimulus.at, last_at)`.
30. **Порядок старта ветвей `fork`** — в ширину, по объявлению.
31. **Восстановление упавшей фабулы** перезаводит дедлайны от момента
    восстановления и возобновляет подписки с прежним `since`.
32. **Накопленные на паузе стимулы** применяются в момент `Resume`.
33. **Вход `Goto`** по умолчанию — сырой вход покидаемого узла, иначе вход
    контейнера.
34. **Счётчики визитов не удаляются** при смене версии, даже для исчезнувших
    узлов: иначе новый узел с тем же путём повторил бы id операций, и идемпотентный
    порт молча проглотил бы новый вызов.
35. **`CompleteWait` для `wait` без `output`** завершает узел его входом.
36. **`$runtime.version`** — версия движка на старте фабулы (из `semantics`), а не
    текущая: иначе реплей после обновления движка дал бы другие значения.
37. **Стимулы к завершённой или отменённой фабуле** → `StimulusIgnored(final)`,
    вмешательства → `ControlRejected(final)`.
38. **Дубль по `stimulus_id`** возвращает то же состояние без изменений и одно
    наблюдение `StimulusIgnored(duplicate)`.
39. **`SwapVersion` на упавшей фабуле** разрешён: цепочка ошибки переносится как
    обычные кадры, дальше фабулу оживляют `RetryTask`/`SkipTask`/`Goto`.
40. **Совместимость `call` при смене версии** — полное совпадение
    `name:version@provider` из закреплённого дескриптора.
41. **`Goto` во время ожидания `schedule.after`** запускает сценарий сразу: таймер
    расписания закрывается, дедлайн сценария заводится, вход — в цель.
42. **Стимул, отвергнутый из-за переполненной очереди паузы**, не запоминается в окне
    дедупа: повторная доставка с тем же `stimulus_id` будет принята.
43. **Смена версии с перезапуском узла на упавшей фабуле** восстанавливает её, как
    `RetryTask`.
44. **Терминальные уведомления хоста** (`Completed`/`Failed`/`Cancelled`) доставляются
    хотя бы один раз; их идентифицирует пара `(fabula_id, version)` перехода.
45. **Задержка ретрая** считается в секундах и режется потолком до построения
    `timedelta`: огромный номер ретрая даёт потолок, а не переполнение.
